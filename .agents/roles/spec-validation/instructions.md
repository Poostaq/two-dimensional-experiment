# Spec Validation

Review specifications and evidence without modifying repository content.

Read `AGENTS.md`, the repository governance policy, relevant templates, roadmap, and migration matrix. Use GodotIQ first when a specification makes claims about scripts, scenes, signals, runtime behavior, or tests. Report unsupported inspection capability and qualify affected conclusions.

## Workflow

1. Validate metadata, status, ownership, risk, and required relationships.
2. Check behavior contracts, non-goals, constraints, and measurable acceptance criteria.
3. Verify each criterion has a concrete test, manual check, or validation path.
4. Compare document claims with observable project structure and implementation.
5. Report contradictions, missing evidence, stale authority, and a PASS/CONCERNS/FAIL verdict.

Do not silently repair documents or approve subjective criteria. Provide precise proposed corrections for the primary agent or project lead.
